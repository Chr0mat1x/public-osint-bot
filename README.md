# OSINT-бот по публичным данным

Telegram-бот на Python, который агрегирует **только публичные данные, доступные
без авторизации**: существование публичного профиля, публичное отображаемое имя,
ссылки на публичные профили, официальные реестры и публичные данные блокчейна.

Работает сразу после ввода ключей: `python bot.py`.

## Четыре режима работы

| Режим | Команда | Что делает |
|---|---|---|
| **Поиск следа** | `/find` | публичные профили, посты, репозитории, форумы |
| **Доказательный пакет** | `/evidence` | данные о схеме мошенничества для банка и полиции |
| **Мониторинг реестров** | `/watch` | следит за изменениями в официальных реестрах |
| **Свой след** | `/mytrace` | что о вас видно публично + проверка пароля в утечках |

## Что бот собирает и что не собирает

| Собирает | Не собирает |
|---|---|
| username (логин) | телефоны |
| публичное отображаемое имя | домашние адреса |
| ссылки на публичные профили | паспортные данные, ИНН/СНИЛС |
| публичные посты и описания | e-mail из утечек |
| официальные реестры (юрлица, отчётность, санкции) | содержимое слитых баз |
| публичные данные блокчейна | закрытые/приватные профили |
| регистрационные данные домена | данные владельца домена, скрытые приватностью |

Никакого обхода авторизации, капчи и закрытых профилей. Если поисковик показывает
анти-бот челлендж, источник **пропускается** и это видно в отчёте.

**Чего в проекте нет и не будет:** подключения слитых баз, поиска по номеру
телефона, деанонимизации владельца криптокошелька или домена. Такие функции
превращают инструмент в средство торговли персональными данными, а не в OSINT.

## Источники

| Источник | Что берёт | Нужен ключ |
|---|---|---|
| `telegram_public` | публичное веб-превью `t.me` и публичные посты каналов | нет |
| `search_engines` | DuckDuckGo / Bing HTML / SerpAPI / Azure Bing | для SerpAPI и Azure |
| `github_public` | публичный профиль, публичные репозитории, похожие логины | нет (токен поднимает лимиты) |
| `forums_public` | Reddit, Hacker News (Algolia), Stack Exchange | нет |
| `registries_public` | GLEIF (юрлица), SEC EDGAR, Wikidata, OFAC SDN | нет |
| `domain_public` | RDAP, DNS, Certificate Transparency, urlscan, Wayback, ip-api | нет |
| `crypto_public` | Bitcoin (blockchain.info), Ethereum (Blockscout), TRON (Tronscan) | нет |
| `breach_public` | HIBP k-anonymity (пароли), каталог утечек | для e-mail |

Все перечисленные API проверены живыми запросами. OpenSanctions и Blockchair
требуют платный ключ, поэтому заменены: санкции берутся из официального
публичного списка OFAC SDN, блокчейн — из blockcypher/Blockscout/Tronscan.

## Настройка ключей

Просто запустите бота — при первом старте он сам спросит ключи и сохранит их:

```bash
python bot.py
```

Мастер спросит:

1. `BOT_TOKEN` — токен от [@BotFather](https://t.me/BotFather). **Обязателен.**
2. Поисковый провайдер — по умолчанию `auto` (без ключа).
3. `SEARCH_API_KEY` — спрашивается только для `serpapi` / `bing`.
4. `GITHUB_TOKEN` — опционально, поднимает лимиты GitHub API.
5. `HIBP_API_KEY` — опционально, для проверки e-mail в утечках.
6. `PROXY_LIST` — опционально, список прокси через запятую.

Результат сохраняется в `config.yaml` (права `600`, файл в `.gitignore`).

Если предпочитаете файл вручную:

```bash
cp config.example.yaml config.yaml
$EDITOR config.yaml
```

Любое значение можно задать переменной окружения, она перекрывает файл:
`BOT_TOKEN`, `SEARCH_API_KEY`, `GITHUB_TOKEN`, `HIBP_API_KEY`, `PROXY_LIST`.

### Провайдеры поиска

| Значение | Ключ | Комментарий |
|---|---|---|
| `auto` | не нужен | **рекомендуется.** DuckDuckGo, при анти-бот челлендже — фолбэк на Bing HTML |
| `duckduckgo` | не нужен | только публичная HTML-выдача DuckDuckGo |
| `bing_html` | не нужен | только публичная HTML-выдача Bing |
| `serpapi` | нужен | стабильная выдача, платный |
| `bing` | нужен | Azure Bing Web Search API |

С датацентровых IP DuckDuckGo часто отдаёт челлендж `anomaly.js`. Режим `auto`
в этом случае автоматически переключается на Bing HTML. Для продакшена
надёжнее `serpapi` или `bing` с ключом.

## Проверка на тестовом username

В Telegram отправьте боту:

```
/find torvalds
```

Ожидаемо: профиль `github.com/torvalds` и репозитории в разделе **ТОЧНО**,
упоминания из поиска в **НЕЯСНО**, блок «Публичные профили» и статус источников.
Второй такой же запрос обслуживается из кэша (в шапке будет «из кэша»).

Другие тестовые значения: `durov`, `telegram` (каналы с публичными постами).

### Доказательный пакет (`/evidence`)

Собирает публичные данные о **схеме и реквизитах** мошенничества, а не о человеке.
Подходит для приложения к заявлению в банк (чарджбэк) и в полицию.

* **Домен** — регистратор, даты регистрации, NS, MX, TXT, поддомены из
  Certificate Transparency, хостинг и его страна, сканы urlscan, архивные копии.
* **Криптокошелёк** — публичная история транзакций, баланс, связанные адреса.
  Поддерживаются Bitcoin, Ethereum, TRON.
* **Организация** — реестр GLEIF (LEI, статус), санкционный список OFAC SDN,
  отчётность SEC EDGAR.

`/evidence_json` отдаёт тот же пакет файлом — его удобно приложить к заявлению.

### Мониторинг реестров (`/watch`)

Бот запоминает «отпечаток» набора записей по субъекту и периодически сверяет его.
Уведомление приходит **только при реальном изменении** — в нём перечислены
добавленные и исчезнувшие записи. Ошибка источника не считается изменением:
снимок не перезаписывается, наблюдение проверяется в следующий проход.

Интервал и лимит наблюдений настраиваются в `monitor` секции конфига.

### Свой след (`/mytrace`)

Работает по вашим собственным данным. Показывает, что о вас видно снаружи, и даёт
конкретные шаги по сокращению следа.

Проверка пароля использует **k-anonymity** HIBP: наружу уходят только первые
5 символов SHA-1 хеша. Сам пароль и полный хеш не покидают ваш сервер —
восстановить пароль по отправленным данным невозможно. Проверка пароля
работает **без ключа**. Для проверки e-mail нужен бесплатный HIBP-ключ.

## Ограничения, зашитые в код

* **Rate-limit:** 10 запросов в сутки на пользователя (окно — календарные сутки UTC).
  Атомарный `UPSERT` в SQLite, гонки исключены.
* **Кэш:** 24 часа, ключ `u<user_id>:<username>|<имя>`. Попадание в кэш **не тратит**
  дневную квоту. Просроченные записи вычищаются при старте.
* **`/delete_me`:** удаляет историю, счётчики лимита, наблюдения со снимками и
  кэш **только этого** пользователя (по префиксу ключа).
* **Наблюдения:** не более `monitor.max_watches_per_user` на пользователя,
  история снимков ограничена 10 на наблюдение — база не растёт бесконечно.
* **Пароль:** при проверке `/mytrace --pw` наружу уходят только первые 5 символов
  SHA-1 хеша (k-anonymity). Пароль и полный хеш остаются на вашем сервере.
* **Таймауты:** на HTTP-запрос `network.request_timeout`, на источник
  `network.source_timeout`, плюс общий таймаут поиска. Падение источника
  изолировано и не влияет на остальные.
* **Ошибки:** капча и 403 → источник помечается «пропущен» с причиной;
  429 → «пропущен (слишком много запросов)»; 5xx и таймауты — ретраи с
  экспоненциальной паузой и джиттером.

## Поток обработки запроса

```
запрос
  → build_query (username + имя)
  → кэш? (если да — отчёт сразу, квота не тратится)
  → rate-limit (10/сутки)
  → источники параллельно, у каждого свой таймаут
  → merge → канонизация URL → дедупликация → фильтр шума
  → скоринг → разметка «точно / вероятно / неясно»
  → отчёт + статус каждого источника
```

Доказательный пакет идёт по тому же принципу изоляции источников: сбой одного
источника попадает в раздел «Источники с ошибками», остальные данные собираются.

Мониторинг работает отдельной фоновой задачей:

```
каждые monitor.interval_hours
  → для каждого наблюдения: опрос реестров
  → сборка «отпечатка» (SHA-256 по ключам записей)
  → отпечаток изменился? → diff по множествам → уведомление владельцу
  → снимок пишется только при изменении, хранится последние 10
```

## Как считается уверенность

Прозрачные правила, каждое видно в отчёте рядом с находкой:

* username совпал в URL профиля: **+0.55**
* логин профиля совпадает точно: **+0.35**
* публичное имя совпало: **+0.25**
* username встречается в тексте: **+0.15**
* платформа с уникальными логинами: **+0.1**; массовая соцсеть: **−0.1**

Порог «точно» — 0.75, «вероятно» — 0.45, ниже — «неясно».

## Прокси

`network.proxy_list` — список вида `http://user:pass@host:port`. HTTP(S)-прокси
работают из коробки. Для `socks5://` доустановите `pip install aiohttp-socks`
и добавьте `connector` в `sources/http_client.py`.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `Telegram отклонил BOT_TOKEN (401)` | неверный токен, возьмите новый у @BotFather |
| Источник «пропущен: анти-бот челлендж» | поисковик заблокировал IP. Смените провайдера на `serpapi`/`bing` или задайте прокси |
| `reddit: HTTP 403` | Reddit блокирует датацентровые IP. Источник пропускается, остальные работают |
| GitHub «API rate limit» | задайте `GITHUB_TOKEN` (30 запросов/мин вместо 10) |
| Certificate Transparency «источник с ошибкой» | certspotter и crt.sh иногда недоступны с датацентровых IP. Поддомены подтянутся из фолбэк-сервиса; если оба молчат — источник честно помечается пропущенным |
| `/mytrace --email` просит ключ | проверка e-mail требует бесплатного HIBP-ключа (`hibp.api_key`). Проверка паролей работает без него |
| `/evidence_json` говорит «сначала соберите пакет» | пакет хранится в памяти процесса — соберите его заново после перезапуска бота |
| Уведомления мониторинга не приходят | проверьте `monitor.enabled` и `monitor.interval_hours` в конфиге; первая проверка создаёт базовый снимок и уведомление не шлёт |
| `python bot.py` просит токен при каждом запуске | не сохранился `config.yaml` — проверьте права на запись в каталоге проекта |

## Примечания

* Бот отвечает только на запросы, сделанные после запуска (`drop_pending_updates`).
* Отчёт выводится в HTML и автоматически режется на части по лимиту Telegram.
* `config.yaml` содержит секреты и уже в `.gitignore` — не коммитьте его.
* Доказательный пакет хранится в памяти процесса: `/evidence_json` работает до
  перезапуска бота. Для долгого хранения выгружайте файл сразу.
* Мониторинг пишет снимок только при изменении данных, поэтому база не растёт
  на каждом проходе.
